# 手机版 HUD 占用检查与优化

检查发现原 HUD 在窄屏中多次换行，机型、模式、流派和 Boss 曲名占用了较多纵向空间；横屏还隐藏了 Boss 技能提示。此次重新排列移动端 HUD，保留关键战斗数据，并把详细背景信息放到暂停面板。

## 实测占用

以下为 CSS 像素，不含设备额外安全区。场景包含九位得分、连击、狂暴/冰霜双增益、三个激活流派，以及带炮台和入场护盾的移动堡垒。

## 调整

- 窄屏顶部固定 44 像素的数据块，保留得分、波次/挑战倒计时、连击、HP、护盾、生命、火力等级与临时增益；增益出现/消失不会改变 HUD 高度。
- 模式、难度、完整机型武器名称、进化、激活流派和 Boss 曲名在暂停面板查看。手机不再常驻显示编队与流派长文本。
- Boss 保留名称、阶段/入场护盾、剩余炮台、血条和技能状态。横屏把技能提示放到血条上方同一行，恢复蓄力/弱点等重要提示的可见性。
- 暂停按钮保留 44×44 像素；手机 EMP 从 80×80 收为 64×64，保留完整触控区域与冷却环。
- 使用原有安全区 padding 和实时 HUD 边界计算，Boss 入场位置、敌机开火边界和玩家活动区随新布局更新。

## 验证

`node test/hud.mobile.test.js` 覆盖 280×720、320×568、360×640、390×844、430×932、568×320、667×375、844×390、932×430、1280×800 共十种尺寸，检查普通与 Boss 状态、关键字段可见、触控尺寸、横向溢出、战场边界同步、增益消失时高度稳定、暂停详情、运行时横竖屏切换，并模拟额外顶部与左右安全区。

另通过 EMP 三尺寸浏览器双指操作、冷却/暂停、玩法流程、鼠标/触屏跟随、Boss 连续移动等回归。测量原始记录在 `test/reports/mobile-hud.json`，截图由测试写入 `test/artifacts/`。

本次为浏览器尺寸与触控模拟，尚未重新构建安装包或做真机刘海/挖孔屏验收。未调整战斗数值；HUD 边界变小会实际增加可活动区域，旧版使用固定 HUD 替身的长局数据不代表新版布局下的真人难度。
